# Catatan referensi upstream integrasi sing-box/libbox

Catatan riset untuk implementasi Android Tunelio. Source/API di bawah merujuk sing-box `v1.14.3` pada 26 Oktober 2026; pin versi upstream dan build binding harus tetap satu versi.

## Fakta API dan arsitektur

- Android client resmi menyebut SFA menyediakan manajemen konfigurasi sing-box dan implementasi platform seperti TUN transparent proxy: <https://sing-box.sagernet.org/clients/android/>.
- Sing-box mengeluarkan `libbox.aar` melalui `gomobile bind`. Builder upstream `cmd/internal/build_libbox/main.go` membangun Android API 24 dan Android API 21 legacy; menggunakan package `io.nekohasekai`, nama library `box`, build tags resmi, linker flags dari release, dan default bind target Android untuk ABIs yang didukung: <https://github.com/SagerNet/sing-box/blob/v1.14.3/cmd/internal/build_libbox/main.go>.
- Builder v1.14.3 mencari Android SDK dan NDK, lebih memilih NDK `28.0.13004108`, dan memerlukan OpenJDK 17. Source `experimental/libbox/platform.go` mendefinisikan `PlatformInterface` dan 33 metode terkait TUN, interface/network monitor, DNS, notifikasi, shell, pengguna, bridge. Source `experimental/libbox/tun.go` memberi `TunOptions` termasuk alamat, DNS, MTU, auto-routes/include/exclude package. Sumber: <https://github.com/SagerNet/sing-box/blob/v1.14.3/cmd/internal/build_shared/sdk.go>, <https://github.com/SagerNet/sing-box/blob/v1.14.3/experimental/libbox/platform.go>, <https://github.com/SagerNet/sing-box/blob/v1.14.3/experimental/libbox/tun.go>.
- Core dijalankan melalui `Libbox.Setup`, `CommandServer`, `StartOrReloadService(config, overrideOptions)`, `CloseService`/`Close`; Android API mengimplementasikan `PlatformInterface.OpenTun` lewat `VpnService.Builder` dan menyerahkan FD established TUN kembali kepada core. Source: <https://github.com/SagerNet/sing-box/blob/v1.14.3/experimental/libbox/setup.go>, <https://github.com/SagerNet/sing-box/blob/v1.14.3/experimental/libbox/command_server.go>, reference Android service <https://github.com/SagerNet/sing-box-for-android/blob/dev/app/src/main/java/io/nekohasekai/sfa/bg/VPNService.kt> dan <https://github.com/SagerNet/sing-box-for-android/blob/dev/app/src/main/java/io/nekohasekai/sfa/bg/BoxService.kt>.
- Counter trafik tersedia lewat `CommandClient` dengan `CommandStatus`; `StatusMessage` berisi `Uplink`, `Downlink`, `UplinkTotal`, `DownlinkTotal`, `TrafficAvailable`. Source: <https://github.com/SagerNet/sing-box/blob/v1.14.3/experimental/libbox/command.go>, <https://github.com/SagerNet/sing-box/blob/v1.14.3/experimental/libbox/command_client.go>, <https://github.com/SagerNet/sing-box/blob/v1.14.3/experimental/libbox/command_types.go>.
- Android mengharuskan `VpnService.prepare()` untuk persetujuan user, manifest `android.permission.BIND_VPN_SERVICE` dengan intent `android.net.VpnService`, `protect()` untuk mencegah loop routing, `Builder.establish()` untuk memperoleh TUN FD, foreground lifecycle, dan menutup descriptor ketika `onRevoke()`: <https://developer.android.com/develop/connectivity/vpn>.
- Manifest aplikasi Android SFA v1.14.3 mendeklarasikan `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_SYSTEM_EXEMPTED`, `FOREGROUND_SERVICE_SPECIAL_USE`, `POST_NOTIFICATIONS`; VPN service menggunakan tipe `systemExempted`: <https://github.com/SagerNet/sing-box-for-android/blob/dev/app/src/main/AndroidManifest.xml>.
- Expo Native Modules API mendukung modul Kotlin lokal; proyek membuat module di `modules/<name>`, module Expo ditautkan setelah Prebuild: <https://docs.expo.dev/modules/get-started/> dan <https://docs.expo.dev/modules/overview/>. Kode native memerlukan Development Build/custom app client, bukan Expo Go: <https://docs.expo.dev/develop/development-builds/introduction/>.
- Proyek Tunelio tidak mempunyai `android/`/`ios/`, Go pada PATH, Android SDK atau NDK. Expo project stack memakai Expo `~57.0.24`, RN `0.86.3`; managed Mobile README menyatakan Android APK/AAB final dibuat via Dashboard, jangan jalankan release build di Sandbox.
